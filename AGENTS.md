# AGENTS.md

Guidance for the standalone `jev-benchmarks` repository.

All model calls must use the installed `jev` CLI from <https://github.com/vilinski/jev>;
never call vendor inference APIs directly or read API keys from Python. Live calls
cost money. Saved result analysis and report generation are offline. Preserve real
partial runs, errors and capability limitations. Never print or commit credentials.

## Benchmark report and its SEO

The published report is <https://ai.vilinski.dev/jev-benchmark/>, generated by
`report.py` from the model/route registry and `results/*.json`: `<name>.json` is the 60-item own set (`run.py`, 3 runs),
`hf_<name>.json` a 1,100-item sample of the public jev-bench (`run_hf.py`, downloads the data itself). `site.py` then builds the
whole `ai.vilinski.dev` tree into `site/` (landing page, `/decision-models/`, `/jev-benchmark/`,
`/coding-agents/`), each page with its own `og.png`. Never change files on the server directly: build here, upload only after the owner agrees.

```sh
mise run bench          # resume all explicitly selected model/route combinations, then generate report and site
cd jev-benchmarks
python3 run.py <typesafe|celeris|cloudflare|openai|openai-chat> 3 results/<name>.json     # 180 calls, costs money
python3 run_hf.py <provider> results/hf_<name>.json                                        # 1,100 calls at the default JEVBENCH_PER=50
REPORT_URL=https://ai.vilinski.dev/jev-benchmark/ python3 report.py && python3 site.py <coding-agents.html> [<template.html>]
```

After every regeneration keep the SEO state current:

- The generator rewrites `<title>`, description, Open Graph/Twitter tags and the
  JSON-LD `TechArticle` (with `dateModified`) from the data and today's date. Set
  `REPORT_URL` (default is the published URL) so the canonical and `og:url` are emitted.
- The report is deployed as `index.html` (plus `og.png`) under `/jev-benchmark/` of
  `ai.vilinski.dev`, which hosts related LLM-evaluation content. That host's `sitemap.xml`
  entry needs its `lastmod` bumped to the deploy date; its `robots.txt` already points to
  the sitemap. The old `vilinski.dev/jev-benchmark/` path only redirects (301). The
  generator's own `robots.txt`/`sitemap.xml` (`REPORT_SITE_FILES=1`) are only for a report
  hosted at a site root.
- `report.py` also draws `og.svg` and rasterizes it to `og.png` (1200x630, macOS `sips`;
  elsewhere an existing `og.png` is reused). Deploy `og.png` next to `index.html`. The
  `og:`/`twitter:` title and description are deliberately short (about 45 and 100 chars)
  because LinkedIn, X and Bluesky cut longer text; `<title>` and the meta description stay long.
- The byline and JSON-LD `author` link to the profile at https://andreas.vilinski.dev/.
- Re-read all methodology and conclusions in `report.py` against the new numbers before deploying.
- `model_registry.json` defines one distinct model/route combination per row. Use `run_variants.py`; legacy `run.py`, `run_hf.py` and `scoring.py` are retained for historical results.
- Unsupported questions are separate from request errors, typed refusals and credential/quota exclusions. Never manufacture completed runs or silently omit capability limits.
- Keep the README and GitHub repository homepage pointing to the published report.
